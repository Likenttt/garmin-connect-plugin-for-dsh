# 独立 MCP 共享工作台验收

日期：2026-11-05。环境：本机 macOS、Harness 0.2.1-rc.5（Cordis 4.0.5）、Node 22.23.4 / Harness Electron Node 24.21.0。

## 本轮实现

- 独立 MCP 显式使用 `--workspace [scopeId]`；旧的单账号环境变量启动方式保留。
- Harness 与独立 MCP 共用同一工作区的账号目录、时间线服务、SQLite 备注和登录控制器。
- 一个工作区只有一个会话运行实例。Harness 已运行时复用其本地服务；无 Harness 时首次请求按需启动一个共享进程，无活动五分钟后退出。账号数不等于进程数。
- 网页使用一次性入口票据、HttpOnly Cookie、同源与 CSRF 检查；内部接口使用独立私密令牌。凭据不会进入前端资源或账号列表结果。
- 账号采用中性备注，新增表单邮箱提示为“请输入这个账号的邮箱”。连接检查、登录、添加、编辑、移除及导出配有 SVG 图标。
- “检查全部连接”最多同时检查三个账号，展示进度和可用、需登录、暂不可用统计，支持取消；隐藏或卸载后停止继续排队，不自动开始 MFA。

## 实际页面结果

1. ego 浏览器成功打开独立工作台，读取到与 Harness 一致的三个原有账号。
2. 独立页点击“检查全部连接”：完成 3/3，可用 3，需登录 0，暂不可用 0。
3. 新增账号表单展示“账号备注”和指定邮箱提示；未保存测试账号。
4. 独立页读取到此前 Harness 原生页面保存的“原生工作台验收（可删除）”备注。
5. Harness 原生右栏点击同一个批量检查按钮：完成 3/3，可用 3。原有账号、备注和凭据未改动。

## 针对性验证

- 完整 host / client types / browser bundles 构建通过。
- 本轮七组针对性测试 43 项通过，覆盖工作区发现、独占租约、配置同步、账号与备注服务、MCP 转发、浏览器会话与 CSRF、批量检查调度、Harness 入口。
- Cordis 4.0.5 与 4.1.0 离线运行检查通过：30 个 Harness 工具、16 条路由、启动时零 SDK 实例、首次数据请求才创建客户端，卸载与重启正确清理。
- 真正 stdio MCP 集成使用随机 `/private/tmp` 目录与合成账号，阻断非回环网络：两个连接只创建一个 owner；一边保存备注另一边可读；MCP 列出 31 个工具；关闭适配器后另一连接仍可用。验收后只停止专属测试进程并清理临时目录。

本轮验证了现有会话的连接状态；未重新执行用户交互式 MFA，也未向 Garmin 写入训练。代码仍为本机开发版本，未发布。
