# 动态账号仓库与取消五账号限制

日期：2026-11-05（Asia/Shanghai）。本记录对应未发布的本地开发构建。

## 实现

- Harness 成员页使用动态 SQLite 账号目录，不再给账号总量设置固定上限；提供新增、编辑、保存并登录、移除连接、搜索和每页 20 条的列表。
- 旧 `account1..5` 字段仅作为首次导入来源。保留旧账号 ID、区域、接入方式、修订和原 session 路径；导入完成后以目录为准。删除采用软归档，重启不重新导入旧配置中的记录。
- 账号元数据与凭据分开：目录使用 SQLite；邮箱、Personal Key 和会话路径引用保存在独立的 owner-only 文件中。新存储不保存密码或 inline token；相同身份的旧配置继续为运行时提供内存兼容。文件目录分别要求 `0600` / `0700`，Windows 复用现有 ACL 设施。
- 所有账号消费者使用实时源，先等待目录就绪再选择账号。工具服务和 MFA 控制器按账号修订延迟创建，修改或移除只失效该账号；旧登录结果和旧训练写确认不能落入新绑定。
- SDK client 默认最多保留 8 个，同时最多 4 个操作，空闲 5 分钟回收；列表、账号编辑和本地状态读取均不创建 SDK client，不再启动时对所有账号并行登录。
- 动态 DSH 模式新增分页 `list_garmin_accounts`，仅返回本地连接元数据。原静态工具注册及独立 MCP 环境变量入口保持原有语义。
- 已迁移工作区的旧设置页禁止继续编辑固定槽位，并引导打开原生成员管理，避免两个可写来源。

## 验证

- 完整 Host、客户端类型与浏览器 bundle 构建通过。
- 7 个相关测试组共 81 项通过；另回归旧认证 RPC 39 项通过。不是全量测试记录。
- 新仓库专项覆盖 100 个账号后继续新增第 101 个；元数据操作没有创建 SDK client。另覆盖迁移、归档不复活、作用域隔离、修订冲突、连接池、并发边界和旧请求失效。
- 实际桌面 Cordis 4.0.5 的离线运行时检查通过：30 工具、16 条路由、配置重启、32 次路由清理；合成 client 在工具首次查询时才创建。该检查使用独立临时目录，没有写入用户账号目录。
- 本机 Harness 实际迁移现有 3 个账号成功；大陆主账号实时验证成功，真实训练时间线可读，原 SQLite 备注仍可读取。
- 在原生“成员”页仅保存 3 条标注为验收的 `example.test` 账号，未发起其登录；第 4、5、6 条保存均成功，页面显示 6 个成员，并保留“添加账号”入口。
- 验收后只归档上述 3 条测试连接，恢复原有 3 个账号。未修改原账号凭据或向 Garmin 写入训练。
- 完全退出并重开 Harness 后，仍为原有 3 个活动账号，测试连接未复活；旧设置页显示动态仓库提示，“打开账号管理”可返回原生成员页。

## 边界

“无限”指不设固定产品数量上限，网络并发与同时保留的 SDK client 仍有边界。目录初始化需要支持 `node:sqlite` 的运行时；本机 Electron 使用 Node 24.21.0。新鲜 Node 20 环境可保留 legacy 模式；已存在的动态目录无法读取时失败关闭，不复活旧账号。

当前为单机、单个 Harness Host 的管理方式；未实现多个 Host 进程之间的目录变更通知，也未增加独立 MCP 多账号工作台。MCP 原有一进程一账号入口保持可用。Windows 真机、真实第六个学员的 MFA 尚未验证；第六账号的控制器与修订流程由合成测试覆盖。
